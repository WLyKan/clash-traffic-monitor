# Windows 应用归因验证

2026-11-10 北京时间，Clash Verge 2.5.8，Mihomo v1.19.32。先验真实连接，再开始工具实现。

## 现用 Clash

通过同一 Windows 用户的本地命名管道读取 `/connections` 和 `/proxies`，从两次快照算字节增量。安装版本运行于 `strict`，首组 25 条 HTTPS 连接均没有进程元数据。对可观测的 TCP 连接，按应用侧 Windows 套接字四元组补进程。四秒实测抓到以下字节增量。

| 应用 | 实际出站类型 | 上传 | 下载 |
| --- | --- | ---: | ---: |
| ChatGPT.exe | Trojan | 28 | 24 |
| Cursor.exe | Shadowsocks | 2985 | 453 |
| chrome.exe | Direct | 0 | 343 |

第二次快照共 31 条连接，其中 14 条 Trojan、6 条 Shadowsocks、11 条直连。28 条连接匹配到 Windows 进程。缺失的进程归入未知。本次使用已有流量，无额外外网下载。

默认工具沙箱令生产管道返回拒绝访问。同用户桌面权限下的只读采样成功。采集工具按当前用户 SID 自动发现管道。

## 隔离对照

在项目目录运行 `python -B tools/verify_mihomo.py`。如安装路径不同，先用 `--help` 查看参数。脚本使用本机 Mihomo 二进制启动一次性回环内核、HTTP 转发节点和两个本地目的服务。测试过程用 TCP CONNECT 保持连接，再比较上传和下载计数。

- `curl.exe` 和 `python.exe` 同时走测试代理，均返回匹配的进程名与路径，上传与下载字节随传输增长。
- 另一条 `curl.exe` 走 `DIRECT`。实际转发节点只处理了两条代理连接，直连请求独立到达目的服务。
- 三个目的 POST 均收到 98,304 字节。隔离内核运行在独立目录和端口，临时服务和进程随测试关闭。

Mihomo 快照只包含活跃连接。两次采样间完成的连接和关闭前的尾量可能无法归到应用。对内核总计与已观察连接的差值单独展示，因为其中可能包含直连。
